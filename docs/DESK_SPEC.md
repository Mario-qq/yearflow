# 个人主工作台（/desk）—— 规格与实施提示词 v1.1

> 定位：从 2026-10-16 起 YearFlow 升级为 **年度计划甘特图 + 个人主工作台** 两大核心模块。
> 甘特图管「这一年往哪走」，工作台管「今天、这周具体做什么」。
> 本文是工作台范围内的唯一事实来源（同 POMODORO_SPEC / ANNUAL_SPEC 的地位）；与 SPEC.md 冲突时，工作台范围以本文为准。
> **已拍板（2026-10-16）**：布局 A 周历七列 · 紧急度三档 · 跟进只分「待告知 / 待下发」· 工作台数据**全部上云同步**，手机端不显示工作台 · **挪到下周**是一等功能（§2.4）· 每天自动全库备份，出问题可整库回滚。

## 一、要解决的问题（负责人原话 → 设计回应）

| # | 现状（手工记录） | 痛点 | 工作台怎么接 |
|---|---|---|---|
| 1 | 手工建一周日历（周一~周日） | 纸面/文档无法联动、过期事项要手抄 | **周历七列**是主界面骨架，保留你的习惯 |
| 2 | 每天的工作待办 | 分不出紧急度 | 待办带 **三档紧急度** + 可选截止日，临近截止自动提档显示 |

## 二、主界面（布局 A 已定，细节以 W0 原型确认为准）

### 2.1 布局 A：周历七列 + 今日加宽 + 右栏

```
┌ 顶栏（现有，加「工作台」导航） ──────────────────────────────────────────────┐
├─ 今日脉搏：10月16日 周五 · W42 │ 还剩 2 件紧急 · 张三那有 3 件要说 · SAP 还没学 │ ◆ SAP MM 结业 还有 23 天 ─┤
├─ 快速添加 [ 写一句话：!紧急  @张三  周三  #SAP  每周一 … ] ─────────────────────────────┤
├──────┬──────┬──────┬──────┬────────────┬─────┬─────┬───────────────┤
│ 周一 │ 周二 │ 周三 │ 周四 │  周五·今天  │ 周六 │ 周日 │ 跟进（按人）  │
│ ✓ 6  │ ✓ 4  │ ✓ 5  │ ✓ 7  │ ▣ 学习卡    │      │      │  张三 3  ▸    │
│ 1件未│      │      │      │ ─ 年度计划 ─│      │      │  李四 1  ▸    │
│ 完成 │      │      │      │ ─ 例行 ──── │      │      │ ───────────── │
│      │      │      │      │ ─ 待办 ──── │      │      │ 收件箱（未排期）│
│      │      │      │      │ ─ 跟进到期 ─│      │      │  · …          │
└──────┴──────┴──────┴──────┴────────────┴─────┴─────┴───────────────┘
```

- 列宽：今天 1.8fr，其余工作日 1fr，周末 0.7fr（有事项时自动 1fr）；右栏 300px，可折叠。
- 过去的日子：已完成的收成「✓ N」，未完成的待办**不留在过去**，派生显示到今天的「顺延」分组并带「拖了 N 天」（不写库，只派生）。
- 未来的日子：正常显示，拖拽到哪天就排到哪天。
- 周切换：← 本周 →，`T` 回到本周；周一自动出现「本周开局」条（见 6.3）。

### 2.2 一天之内的分区顺序

1. **学习卡**（学完后收成一行「✓ 已学 47 分钟 · 连续 5 天」）
2. **年度计划**：甘特图当天应打卡的任务（复用 `derive/dayPanel.dayEntries`），一键打卡 / 开专注 —— 与甘特图联动的主通道
3. **例行**：今天该做的日常/周常/月常；漏做的周常在本周内、月常在本月内以「补做」挂在今天
4. **待办**：按紧急度 → 截止日 → 手动顺序排；顺延的在最上方
5. **跟进到期**：设了提醒日且今天到期的跟进

每个分区标题 11px、可折叠；空分区不渲染。行高 28px，左侧圆形勾选，右侧元信息（紧急色点 / @人 / #目标 / 截止日）。

### 2.3 在哪里用

- 数据全部云同步；**工作台只在电脑宽度（≥768px）出现**：桌面版与电脑浏览器的默认首页都改为工作台，甘特图仍一键可达。
- 手机（<768px）底部导航不加工作台，默认落点仍是打卡页；手机直接打开 /desk 时跳回打卡页。
- 学习卡依赖的甘特任务、打卡、专注记录本来就同步，手机打卡页照常能打学习任务的卡。

### 2.4 挪到下周（重点功能）

场景：这周排不下、或者本来就该下周做的事，要能**几秒内**挪走，而且挪的时候看得见下周已经排了多少。

**① 下周预览列（拖拽目标）**
- 周日右边常驻一条 40px 窄列「下周 ▸」，显示下周总件数与每天的小刻度（件数越多刻度越高）。
- 拖动任何一行时，这条窄列展开成 7 个小格（下一 ~ 下日，各带件数），松手到哪格就排到下周哪天；松在窄列标题上 = 「下周同一天」。
- 拖到「← 本周 →」的 → 箭头上停 600ms，周历翻到下周，可精确放到下周任意位置（再停一次继续翻）。

**② 多选 + 挪动条（批量）**
- `Ctrl+点` 逐个选、`Shift+点` 连续选、在某天空白处按住拖出框选；点列头「全选这天未完成」。
- 选中后底部浮出挪动条：**明天 · 下周一 · 下周同一天 · 选日期… · 放回收件箱**，另有紧急度与删除。一次挪动 = 一条撤销记录（「挪到下周：5 件」）。
- 键盘：`Shift+→` 往后挪一天，`Shift+W` 挪到下周同一天，`Shift+M` 挪到下周一，`D` 打开日期选择（顶部就是这几个快捷项）。

**③ 列头与周收尾的一键批量**
- 每天列头菜单：「这天没做完的 → 明天 / 下周一 / 下周同一天」。
- 周五 17:00 后（或周六、周日打开）「本周收尾」条列出本周所有未完成：**全部挪到下周一** / **按原星期挪到下周** / 逐条处理（每条右侧三个小按钮：下周 · 收件箱 · 不做了）。
- 周一首次打开的「本周开局」负责兜底：上周还有没处理的，同样三种处理方式。

**④ 规则与口径**
- 待办、跟进都能挪；例行事项可以「这一次改到某天」（只改这一次，规则不变，见 3.3）；甘特图的「年度计划」行不能在工作台里挪（改期回甘特图拖 bar）。
- 每次「往后挪」`deferCount + 1`（往前挪不加）；拖延信号用它而不是天数判断（§3.1）。
- 挪动只改 `date`，不碰紧急度与截止日；挪到截止日之后的日期时，行上截止日标红并提示一次。
- 下周格子里只算未完成的待办 + 跟进 + 例行，不算甘特任务（避免数字虚高）。

## 三、四类事项的规格

### 3.1 待办（WorkItem.kind = 'todo'）

- 字段：标题、备注（可选）、紧急度、排期日 `date`（缺省 = 收件箱）、截止日 `dueDate`（可选）、范围 `scope`（工作/生活）、关联目标 `goalId`（可选，仅作标签与筛选）。
- 紧急度三档：🔴 紧急（今天必须）/ 🟠 尽快（本周内）/ ⚪ 普通。截止日 ≤ 明天的事项至少按「尽快」显示、已过截止日按「紧急」显示（只影响显示，不改数据）。
- 状态：open / done / dropped（「不做了」与「做完了」分开，周末小结里分别计数）。
- 拖延信号（小巧思）：同一待办被往后挪 ≥3 次（`deferCount`）或过期顺延 ≥3 天，行尾出现淡色提示「拆小 · 改期 · 删掉 · 转跟进」，点一下即执行，不弹窗。

### 3.2 跟进（WorkItem.kind = 'followup'）

- 字段：在待办基础上加 `person`（对象，输入时按历史出现频率自动补全）、`mode`：**待告知 / 待下发**（不做「等回复」）。
- 右栏按人分组，组内按「挂了几天」倒序；组头显示人名 + 件数 + 最久那件的天数。
- **复制给 TA**（小巧思）：点人名旁的复制，生成一段可直接贴进聊天工具的文字：「张三，同步几件事：1. … 2. …」，复制后可一键全部标为已告知。
- 设了提醒日的跟进，在那天的列里「跟进到期」分区出现。

### 3.3 例行（Routine + RoutineLog）

- 规则：每天 / 每个工作日 / 每周几（多选）/ 每月几号（含「月末」）/ 每月第 N 个周几；可选时间点（只用于排序与提醒）、起止日期、暂停。
- 范围：**工作**（只在工作日出现，遵守休/班标记）/ **生活**（每天都按规则出现）。
- 完成记录 `RoutineLog.id = routineId + ':' + date`（确定性 id ⇒ 两台设备同时勾选不会出两条）。
- 漏做：日常不补；周常挂到本周日；月常挂到月底；「跳过」与「完成」分开记。
- 本次改期：某一次例行可以挪到别的日子（如这周三的周报改到周四），记一条 `RoutineLog{status:'moved', movedTo}`，原日不再显示、新日期出现一次，完成记在原日那条上；规则本身不变。
- 休/班标记 `DayMark`：周历列头右键「标为休息日 / 补班日」。不内置节假日表（2027 年安排尚未发布，手动标两次比维护一张表可靠）。**只影响工作台**，不改甘特图 `weekdays` 规则的口径。

### 3.4 快速添加（一句话建任何东西）

单个输入框，`N` 聚焦，回车创建，下方实时预览解析结果（纯函数 `parseQuickAdd`，vitest 覆盖）：

| 写法 | 结果 |
|---|---|
| `!` / `!!` | 尽快 / 紧急（缺省普通） |
| `@张三` | 变成跟进，对象张三；含「下发/发给/分派」默认待下发，否则待告知 |
| `今天` `明天` `后天` `周三` `下周一` `10.20` `10-20` | 排期日 |
| `截止周五` `ddl 10.31` | 截止日 |
| `#SAP` | 关联目标（按目标名模糊匹配） |
| `每天` `工作日` `每周一三` `每月5号` `每月最后一天` | 变成例行 |
| `~生活` | 范围=生活（缺省：工作日为工作、周末为生活） |

### 3.5 交互与键盘

- 勾选：圆圈填充 + 行淡出滑入「已完成 N」折叠（140ms，统一缓动，减弱动效时直接切换）。
- 拖拽：行在天与天之间、天与收件箱、天与「下周」窄列之间拖动（原生 pointer events，3px 起拖，拖动中只改 transform）；多选时拖任意一行带走全部选中。
- 键盘：`N` 新建 · `J/K` 上下 · `X` 完成 · `1/2/3` 紧急度 · `D` 改日期 · `Shift+→` 往后一天 · `Shift+W` 下周同一天 · `Shift+M` 下周一 · `Enter` 编辑 · `Del` 删除 · `←/→` 切周 · `T` 本周 · `S` 开始学习。全部操作进 undo 栈，`Ctrl+Z` 可撤。
- 命令面板（已有）加入工作台命令。

## 四、和甘特图怎么关联（负责人问 #14 的建议）

**做（有真价值、零重复数据）**
1. **今日「年度计划」分区** = 甘特图当天应打卡任务，打卡/专注结果直接回写甘特点阵。工作台成为甘特计划的每日执行入口，不新增任何数据。
2. **学习卡的内容取自甘特图的学习任务**：甘特任务的打卡规则（如 SAP 一三五、AI 二四）就是学习排程，不在工作台另建一套。
3. **里程碑倒计时**：今日脉搏右侧显示最近 1–2 个未达成里程碑「还有 N 天」——保留你说的「时间观念和紧迫感」。

**可选（只当标签）**：待办 `#目标` 仅用于筛选与显示，**不计入甘特进度**（避免两套口径打架）。

**不做**：待办自动生成甘特 bar；工作台数据进年报。

## 五、学习防忘：六层机制（负责人问 #7）

科学依据：执行意图（Gollwitzer，「如果…就…」计划让执行率显著提高）、习惯锚定、「绝不连断两天」、降低启动门槛。

| 层 | 机制 | 落地 |
|---|---|---|
| 1 | **固定锚点** | 设置「我会在 [午饭后 12:30] 学习」，学习卡第一行就是这句话（可按星期分别设） |
| 2 | **到点提醒** | 到点未开始 → 桌面系统通知；最晚时间（如 21:00）仍未学 → 第二次提醒「15 分钟也算」。**需要桌面版常驻**：关窗改为收进托盘 + 可选开机自启 |
| 3 | **首屏醒目** | 没学之前学习卡置顶、主色描边轻呼吸（减弱动效时静态）；学完收成一行 |
| 4 | **一键开始** | 「开始 45 分钟」直接起番茄钟并绑定当天的学习任务，结束自动打卡（复用现有结果卡）；另有「只有 15 分钟？开始短版」 |
| 5 | **不连断两天** | 昨天断了 → 今天卡片文案变成「昨天断了一天，今天别连断」 |
| 6 | **周目标代替日完美** | 显示「本周 3/5 天」环，周末可补，避免一次断掉就放弃 |

今天学什么：当天应打卡的学习任务里，按「进度落后最多 → 最久没碰」排第一，点一下可换下一个。哪些目标算「学习」在设置里勾选（如 AI、SAP、Python）。

学习完成的口径：当天学习类任务的专注净时长合计 ≥ 每日目标分钟数，或手动打卡「完成」。

## 六、小巧思清单（每条都要真有用，不做装饰）

1. **今日脉搏**：一句话说清今天的局面（紧急几件、谁那有事要说、学没学），不是一排数字。
2. **复制给 TA**：跟进按人一键生成可粘贴的消息。
3. **本周开局**（周一首次打开）：上周没做完的 N 件 →「全部带到本周 / 逐条处理」。
4. **本周收尾**（周五 17:00 后 / 周末）：完成 N 件 · 跟进清掉 N 件 · 学习 N 天，一行小结（可复制，二期周会素材的来源）+ 未完成一键挪到下周（§2.4③）。
5. **拖延信号**：顺延 ≥3 天的待办给出「拆小 / 改期 / 删掉 / 转跟进」。
6. **清空当天**：今天的事全部处理完，列底浮现一行安静的「今天清空了」。
7. 深色主题一等公民，数字 `tabular-nums`，动效只留功能性的。

## 七、数据模型（domain.ts 增量，W1 落地）

```ts
export type Urgency = 'urgent' | 'soon' | 'normal';
export type WorkScope = 'work' | 'life';

/** 工作台事项：待办与跟进同表（跟进 = 带对象的待办），便于互转与统一排序 */
export interface WorkItem {
  id: string;
  kind: 'todo' | 'followup';
  title: string;
  note?: string;
  urgency: Urgency;
  scope: WorkScope;
  date?: string;        // 排期日 YYYY-MM-DD；缺省 = 收件箱
  dueDate?: string;     // 截止日
  person?: string;      // 跟进对象
  mode?: 'inform' | 'dispatch';           // 待告知 / 待下发
  goalId?: string;      // 仅标签，不计入甘特进度
  deferCount?: number;  // 被往后挪的次数（拖延信号用），缺省 0
  status: 'open' | 'done' | 'dropped';
  doneAt?: string;      // ISO
  order: number;
  createdAt: string; updatedAt: string; deletedAt?: string;
}

export interface RoutineRule {
  type: 'daily' | 'workday' | 'weekly' | 'monthlyDay' | 'monthlyNth';
  daysOfWeek?: number[];             // weekly：0=周日…6=周六
  monthDay?: number;                 // monthlyDay：1–31，-1 = 月末
  nth?: number; weekday?: number;    // monthlyNth：第 nth（-1=最后一个）个 weekday
}

export interface Routine {
  id: string; title: string; note?: string;
  scope: WorkScope; rule: RoutineRule;
  time?: string;          // HH:mm，排序与提醒用
  startDate: string; endDate?: string; paused?: boolean;
  order: number;
  createdAt: string; updatedAt: string; deletedAt?: string;
}

export interface RoutineLog {
  id: string;             // `${routineId}:${date}` 确定性 id
  routineId: string; date: string;   // date = 规则算出的原日期
  status: 'done' | 'skipped' | 'moved';
  movedTo?: string;                  // status=moved：这一次改到哪天；在新日期上完成后 doneAt 记在本条
  createdAt: string; updatedAt: string; deletedAt?: string;
}

/** 休/班标记：只影响工作台「工作日」判定 */
export interface DayMark {
  id: string;             // = date
  date: string; type: 'off' | 'work'; note?: string;
  updatedAt: string; deletedAt?: string;
}
```

- 设置（本地，不同步）：`AppSettings.desk = { studyGoalIds, studyMinutes, anchorText, remindAt, lastCallAt, weekLayout… }`。
- 落库：Dexie **v4** 新增 4 表 → 加进 `TABLE_NAMES`（`src/store/types.ts`，它同时驱动同步、备份、清库）→ `lib/backup.ts` zod → Supabase 迁移 `0005_desk.sql`（建 4 表 + RLS + 把表名加进 `upsert_rows` 白名单；按 0001 的告诫，**只追加不重写**）。
- ⚠️ 上线顺序：负责人先在 Supabase 执行 0005，再部署前端。**W1 同时修掉「云端缺一张表 ⇒ 所有表同步停摆」**（0004 时暴露过）：拉取/推送逐表隔离失败，缺表只跳过那一张，状态点提示「云端缺表 xx，请执行迁移」。
- **每日自动备份 + 整库回滚**：
  - 桌面版每天首次启动（及每次「导入/清空/载入示例」之前）把全库 JSON 写到 `%APPDATA%/YearFlow/backups/yearflow-YYYYMMDD-HHmm.json`，保留最近 30 份每日备份 + 最近 10 份操作前备份；走现有 `exportBundle` ⇒ 所有表自动包含，不再区分表。
  - 设置页「备份与回滚」：列出备份（时间、各表行数、与当前相比的差异条数），选一份「回滚到这一刻」——回滚前先自动备份当前状态，回滚本身可再回滚。
  - 回滚会传播到所有设备：恢复走 `replaceAllData`，repo 写入时重盖 `updatedAt`（`src/db/repos/baseRepo.ts:34`），被替换的行打墓碑 ⇒ 下次同步以回滚版本为准。W1 加一条测试锁住这个行为。
  - 网页版没有文件系统权限，不做自动备份（桌面版是主力机，备份放这一处足够）。
- 派生全部放 `src/lib/derive/desk.ts`（纯函数 + vitest）：某天出现哪些例行、顺延与拖了几天、跟进按人聚合、今日脉搏句子、学习今日推荐与完成判定、本周小结。
- 全部写操作走 `execute(command)` 进 undo 栈；删除软删除。
- 容量：按每天 20 条估一年约 7 000 行，内存全量 + 派生 memo，无需分页。
