## 一、项目定位

为**单人使用**构建一个以甘特图为绝对核心的个人年度计划管理网站 **YearFlow**。

它解决三个问题：
1. **年度规划**：一年中要推进哪些学习/生活目标，各阶段何时开始、何时结束（经典甘特图）。
2. **每日坚持**：每天有没有真的在做这些事（打卡系统），并且打卡结果**直接可视化叠加在甘特图上**，一眼看出"计划排了、但没执行"的空洞区间。
3. **月度复盘**：每月回顾执行率、投入时长、连续天数，写复盘笔记。

用户画像：一人使用，主力设备是电脑（大屏查看与编辑），手机端用于每日快速打卡与查看今日任务。使用节奏：年初制定计划 → 每天打卡 → 每月复盘。

**核心设计哲学：甘特图不是众多视图之一，而是首页、是主战场。其他一切功能（打卡、统计、复盘）都是配角，并尽量把信息回流到甘特图上呈现。**

## 二、技术栈（明确指定，不要替换）

- **前端**：React 18 + TypeScript + Vite
- **样式**：Tailwind CSS + CSS variables 设计令牌，深/浅色双主题（跟随系统 + 手动切换）
- **状态管理**：Zustand（自实现 undo/redo 历史栈）
- **日期**：dayjs（isoWeek、customParseFormat 插件），全部按本地时区处理，一天的边界是本地 00:00
- **甘特图渲染**：**不使用任何现成甘特图库**（frappe-gantt / dhtmlx 等都不用）。用 SVG + React 自绘时间轴与任务条，原因：需要在任务条上叠加每日打卡点阵与热度条，现成库无法实现且视觉不可控。拖拽用原生 pointer events 自己实现（不要用 dnd 库做 bar 拖拽，精度不够）。
- **图表（统计页）**：recharts
- **本地持久化**：Dexie.js（IndexedDB），所有变更自动保存（防抖 500ms）
- **数据备份**：JSON 一键导出 / 导入（导入前 schema 校验与版本迁移）
- **移动端**：响应式 + PWA（vite-plugin-pwa，可安装到手机主屏，离线可用）
- **云同步（必做，见第十节）**：Supabase 免费档，本地优先架构，电脑与手机数据互通
- **部署**：Vercel 免费档，手机浏览器访问同一网址并安装 PWA

## 三、领域模型（TypeScript 定义，唯一事实来源）

```typescript
/** 年度目标 = 甘特图的一条泳道（swimlane），如 "SAP系统" */
interface Goal {
  id: string;            // nanoid
  name: string;
  color: string;         // 主题色，取自预设色板
  icon?: string;         // emoji
  order: number;         // 泳道排序
  archived: boolean;
  createdAt: string;     // ISO
  updatedAt: string;
  deletedAt?: string;    // 软删除（同步用）
}

/** 阶段任务 = 甘特图上的一根 bar，隶属某个 Goal */
interface Task {
  id: string;
  goalId: string;
  name: string;          // 如 "SAP MM 模块学习"
  startDate: string;     // YYYY-MM-DD
  endDate: string;       // YYYY-MM-DD（含当日）
  progress: number;      // 0-100
  progressMode: 'manual' | 'auto';   // auto = 已打卡天数 / 截至今天的应打卡天数
  status: 'planned' | 'active' | 'done' | 'paused';
  note?: string;         // markdown 备注
  recurrence?: Recurrence;
  order: number;
  trackId?: string;      // 执行轨道归属：同 goal 内 trackId 相同的任务收成一条可折叠的轨道（见 4.3.1）
  dependsOn?: string[];  // 轻量依赖（仅可视化连线与冲突提示，不做自动重排）
  baseline?: { startDate: string; endDate: string };  // 基线快照（原计划）
  updatedAt: string;
  deletedAt?: string;
}

/** 里程碑 = 泳道上的菱形节点，如 "PMP 考试日" */
interface Milestone {
  id: string;
  goalId: string;
  name: string;
  date: string;
  achieved: boolean;
  updatedAt: string;
  deletedAt?: string;
}

/** 打卡规则：定义哪些天"应该做" */
interface Recurrence {
  type: 'daily' | 'weekdays' | 'custom';
  daysOfWeek?: number[]; // custom：0=周日...6=周六，如篮球 = [1,3,6]
}

/** 每日打卡记录 */
interface CheckIn {
  id: string;
  goalId: string;
  taskId?: string;
  date: string;          // YYYY-MM-DD
  status: 'done' | 'partial' | 'skipped';  // 完成 / 做了一点 / 有意跳过
  minutes?: number;
  note?: string;
  createdAt: string;
  updatedAt: string;
  deletedAt?: string;
}

/** 免打卡区间：出差/生病/长假，期间不判缺卡、不断 streak */
interface ExemptionPeriod {
  id: string;
  startDate: string;
  endDate: string;
  goalIds?: string[];    // 缺省 = 全部目标
  reason?: string;       // 如 "春节回家"
  updatedAt: string;
  deletedAt?: string;
}

/**
 * 专注会话 = 一次番茄钟专注（第 7 张表，番茄钟模块新增）。
 * 「真实投入时间」的唯一事实来源；CheckIn 保持「我今天做没做」的语义不变。
 * 只有已结束的会话入库；运行中状态在 localStorage，不入库、不同步、不进 undo。
 * 完整口径见 docs/POMODORO_SPEC.md（番茄钟范围内以该文档为准）。
 */
interface FocusSession {
  id: string;
  goalId?: string;       // 缺省 = 未归类
  taskId?: string;
  date: string;          // YYYY-MM-DD，从 startAt 派生一次后冻结（不随时区漂移）
  startAt: string;       // ISO
  endAt: string;         // ISO
  focusMs: number;       // 净专注毫秒（已扣暂停、已 clamp 到 plannedMs）
  plannedMs: number;
  pauses?: { at: string; until?: string }[];
  outcome: 'completed' | 'stopped' | 'discarded'; // discarded 不计入任何统计
  source: 'timer' | 'manual';
  needsReview?: boolean;
  note?: string;
  createdAt: string;
  updatedAt: string;
  deletedAt?: string;
}

/** 月度复盘 */
interface MonthlyReview {
  id: string;
  month: string;         // YYYY-MM
  content: string;       // markdown
  rating?: number;       // 1-5
  updatedAt: string;
  deletedAt?: string;
}

interface AppSettings {
  theme: 'light' | 'dark' | 'system';
  weekStartsOn: 0 | 1;
  yearInView: number;
  /** 甘特图视图状态持久化：下次打开恢复原样 */
  ganttView: {
    zoom: 'year' | 'quarter' | 'month' | 'week';
    scrollDate: string;          // 视口左缘日期
    collapsedGoalIds: string[];
    gridColumns: string[];       // 左侧网格显示哪些列
    gridWidth: number;           // 左侧面板宽度 px
    showDependencies: boolean;
    showBaseline: boolean;
    filter: { status?: Task['status'][]; goalIds?: string[] };
  };
}
```

派生概念（不入库，实时计算，写成纯函数并配单元测试）：
- **应打卡日**：任务日期范围 ∩ recurrence 规则，再减去命中的 ExemptionPeriod；无 recurrence 的任务默认 daily。
- **缺卡（missed）**：应打卡日 < 今天 且无 CheckIn → missed。
- **streak**：按 Goal 计算当前连续完成天数与历史最长；skipped 与免打卡日不打断，missed 打断。
- **计划偏移**：有 baseline 的任务，实际起止相对基线的偏移天数。

### 4.2 精确尺寸与栅格（按此执行，全部提取为 CSS variables / 常量文件）

- **缩放层级与列宽**：年 = 2.5px/天，季 = 8px/天，月 = 28px/天，周 = 56px/天。缩放切换带 150ms 的宽度过渡动画，并以鼠标位置（或今日线）为锚点保持视觉焦点不跳。
- **行高**：目标分组行 40px；任务行 48px（其中 bar 高 22px、bar 与点阵间距 4px、点阵高 10px、上下留白 6px）；里程碑行合并进任务行渲染。
- **打卡点**：直径 7px，间距随日宽自动对齐日期列中心；日宽 < 10px 时自动切换为热度条模式（高 3px，紧贴 bar 底部）。
- **表头**：双层各 28px。年视图：上层"2026"、下层月份名；季视图：上层月、下层 ISO 周号（W01…）；月/周视图：上层"2026年3月"、下层每日"日期+星期缩写"，今天的日期单元格加主色圆形底。
- **背景网格**：垂直日/周分隔线用最淡的 1px 线；月份分隔线加深一档；季度分隔线再加深并在表头标 Q1-Q4。周末列整列淡灰底纹（深色主题下为淡亮底纹）；免打卡区间整列斜纹底纹并在表头顶部标注 reason。
- **今日线**：2px 主红色垂直线，顶端一个小"今"字标签；加载后自动平滑滚动至视口 1/3 处。

### 4.3 左侧任务网格（专业 PM 工具的关键，不是简单树形列表）

- 结构：目标行（可折叠，显示 icon + 名称 + 本月完成率迷你环形 + streak🔥N + 任务数）→ 其下任务行。
- 任务行为**多列网格**，默认列：名称 / 起止日期（"3.01–5.31"紧凑格式）/ 进度（微型进度条+百分数）/ 状态点。列头右键或"筛选"菜单里可显隐列（可选列：应打卡完成率、偏移天数）。列宽可拖。
- **行内编辑**：单击名称即变输入框改名；单击进度可直接输数字；状态点单击循环切换。全部即时保存并进 undo 栈。
- **左右联动**：hover 左侧行 → 右侧对应 bar 加描边高亮 + 整行淡色背景横贯两侧；反之 hover bar 也高亮左行。单击左行名称区域外的空白 → 右侧平滑滚动把该 bar 带进视口并闪烁一次定位。
- 目标行的时间轴一侧渲染**汇总条**：一根 6px 高的细条覆盖其所有子任务的总时间范围，颜色为目标色 40% 透明度，折叠泳道后仅显示此汇总条 + 聚合热度条（信息不丢失）。
- 网格底部常驻"+ 新建目标"按钮；每个目标分组末尾 hover 时出现"+ 添加任务"幽灵行。

#### 4.3.1 执行轨道（track）

解决的问题：一个目标下同时存在"迭代很快就结束的短命项目"和"持续迭代的长期项目"。后者被拍平成多行散落在时间轴各处，既看不出整条执行路径，又把年度视图淹没。轨道是介于目标与任务之间的一层分组。

- **归属来源**：`Task.trackId`（显式字段，随 tasks 表云同步）。**不从 `dependsOn` 推导** —— 依赖表达时序先后，轨道表达项目归属，二者不等价：同项目的并行任务没有依赖，有先后的任务也未必同项目。
- **成组规则**：只在同一 goal 内成组（分组键 `goalId::trackId`）；组内不足 2 个成员时不成轨道，该任务退回普通行。
- **轨道名**：派生自组内 `startDate` 最早的任务名，无独立存储。
- **默认折叠**，因此持久化的是 `ganttView.expandedTrackIds`（"已展开"）而非"已折叠"。该字段属 AppSettings，本地不同步；归属本身同步，故换设备后轨道照样成形，只是回到默认折叠。
- **折叠行**：左栏 = 折叠箭头 + 轨道名 + 天数加权的聚合进度 +「N 步」徽标（徽标占状态列，那一格对轨道无意义；状态列被隐藏时退回名称列）。时间轴 = 包络汇总条（成员区间并集实心分段，段间浅色间隙表示"这段时间没有任务在推进"）+ 成员打卡的聚合热度条。折叠态只读，单击某段展开轨道并定位到那一段任务。
- **展开行**：轨道行保留（画一条低对比度的包络"括号"条，折叠按钮位置不跳），成员任务缩进列在其下，按 `startDate` 排序。
- **排序**：轨道整块按头任务的 `order` 参与泳道内排序，可整块拖动重排；成员行不可拖（顺序由开始日决定，拖 bar 改期即可）。
- **依赖线**：成员被折叠时端点上浮到轨道包络条；同一轨道内部的依赖线隐藏（由包络条的连续性表达）；多条外部依赖收拢成一条线时点击不删除，提示展开后逐条删。
- **建轨道**：多选任务右键「合成一条轨道」；单个任务右键「归入轨道「X」」/「移出轨道」；目标行右键「按依赖链建轨道」把现有依赖链一次性转成轨道（**一次性辅助导入，不是判定规则**，可 Ctrl+Z 整体撤销）。
- **筛选交互**：`hideOthers` 下任一成员命中就补回整条轨道（否则包络跨度失真）；淡出模式下部分成员命中则临时展开该轨道（折叠条无法区分是哪一段命中），此临时展开不写回持久化。

**已知局限**（都源于"轨道无独立实体"这一取舍）：① 不能单独命名/上色/加备注/加里程碑/单独统计，改了最早那个任务的名字就等于改了轨道名；② 单成员的"项目"无法折叠，粒度不均；③ 不能跨泳道（行布局单位是泳道内的行）；④ 折叠态信息有损（看不到各成员状态色，不能改期/打卡）；⑤ 单层，不支持轨道套轨道。
升级路径：新开 `tracks` 实体表（name/color/note 并纳入同步）即可消除①，`buildTracks` 的输出接口 `TrackIndex` 与全部 UI 层可零改动。

### 4.4 任务 bar 与打卡可视化（灵魂功能）

- **bar**：圆角 6px；左侧实色填充 = progress%，右侧同色 25% 透明度 = 剩余；bar 内左对齐显示任务名（12px，放不下自动溢出到 bar 右侧外部，颜色变正文色）；status=done 降低饱和度并加 ✓；paused 用 45° 斜纹；active 且落后（auto 进度 < 时间进度）时 bar 右上角出现小警示角标。
- **打卡点阵**（月/周级别，bar 正下方对齐日期列）：done=实心目标色；partial=左半实心；skipped=空心灰圈；missed=淡红点；未来应打卡日=8% 透明度占位点；非应打卡日不渲染。今天的点外加一圈主色描边。
- **热度条**（年/季级别）：按周聚合完成率，目标色从 15% → 100% 透明度五档映射；整周全缺 = 淡红；无应打卡 = 不渲染。**这是年视图下判断"排了没做"的核心信号，必须醒目而不刺眼。**
- **点击打卡点** → 就地 popover（不是弹窗）：四个状态按钮 + 分钟 chips(15/30/60/90) + 一行备注输入 + "删除记录"，点外部即关，操作即存。
- **里程碑**：14px 菱形渲染于所属泳道 bar 行内，名称在菱形右侧 11px 小字；achieved 后实心+勾；拖动菱形可改日期。
- **依赖连线**（可全局开关，默认开）：FS 依赖，从前置 bar 右缘到后继 bar 左缘的圆角折线（Bezier 拐角），颜色为中性灰、hover 相关任务时高亮为目标色；hover bar 两端出现小圆点连接柄，从柄拖到另一根 bar 即建立依赖；点击连线可删除。若后继开始日 < 前置结束日，连线变红色警示（不自动改期，只提醒）。
- **基线对比**（可全局开关，默认关）：顶栏"保存基线"把当前所有任务起止快照进 baseline；开启显示后，每根 bar 下方（点阵之上）渲染一根 4px 灰色细条表示原计划，偏移的任务在 tooltip 与网格"偏移"列中显示"+N 天"。

### 4.5 交互手感（好用与否就在这些细节，逐条实现）

- **拖拽移动 bar**：pointer 按下 3px 后进入拖拽；原位置留 30% 透明度虚影；拖动中 bar 跟手（transform，不重排），吸附到天，光标上方浮动显示"3月4日 – 5月17日 (74天)"；拖近视口左右边缘时时间轴自动匀速滚动；松手落位有 120ms 归位动画；Esc 取消。
- **拖拽 bar 左/右缘**：8px 热区，光标变 col-resize，同样吸附与浮动提示；最短 1 天。
- **跨泳道拖拽**：bar 垂直拖到另一目标行 → 改 goalId（bar 颜色随之过渡到新目标色）。
- **框选新建**：在某任务行空白处按下水平拖出日期范围 → 半透明预览条 → 松手弹出仅一个名称输入的迷你气泡，回车创建，Esc 取消。
- **滚动与缩放**：滚轮=垂直滚动；Shift+滚轮或触控板横扫=水平平移；Ctrl+滚轮=以鼠标为锚缩放（在四档间连续插值，松开吸附到最近档位）；按住空格+拖拽=抓手平移。
- **hover 十字定位**：hover 时间轴任意处，表头对应日期单元格高亮、所在行整行淡背景，形成十字准线，帮助对齐"哪一天×哪个任务"。
- **多选**：Ctrl/Cmd+点选、Shift+点选连续、或在行间空白处框选多个 bar；选中集显示统一描边；出现底部浮动操作条（见第六节）。
- **右键菜单**（bar）：编辑详情 / 标记完成 / 暂停⇄恢复 / 复制并顺延 / 从此日拆分 / 保存为基线 / 删除。（时间轴空白右键：在此日新建任务 / 新建里程碑 / 添加免打卡区间。）
- **tooltip**（hover 400ms 出现）：任务名、日期范围与天数、进度、应打卡/已打卡/缺卡数、当前 streak、基线偏移。
- 所有可点元素有 hover 态；所有拖拽保持 60fps（拖拽过程只改 transform，落手才提交状态）。

### 4.6 mini-map、筛选与聚焦

- **mini-map**：底部 28px 全年缩略——每个目标压缩成一条 2px 色线段表示任务分布，今日一根红点线；视口取景框半透明可拖动/点击跳转。
- **筛选**（顶栏）：按状态、按目标多选过滤；过滤时其余行淡出而非移除（保持空间感），再点一次"仅显示"才真正收起。
- **聚焦模式**：双击目标行 → 只展开该目标并放大到其时间范围，其余泳道折叠成汇总条；再双击退出。
- **导出**：当前视图导出 PNG（含左侧网格），用于分享或存档年度计划快照。

### 4.7 键盘快捷键

`T` 回到今天，`+/-` 缩放，`←/→` 平移一周，`Shift+←/→` 平移一月，`Ctrl+Z / Ctrl+Shift+Z` 撤销重做，`N` 新建任务，`M` 新建里程碑，`D` 今日打卡面板，`B` 切换基线显示，`/` 命令面板，`Esc` 取消当前操作/关闭浮层，`Del` 删除选中（带确认）。顶栏"?"图标弹出快捷键速查表。

## 五、今日打卡面板（每日高频入口，移动端首屏）

- 顶部：日期 + "2026 第 N 天 · 年度进度 x%"细进度条。
- 按目标列出**今天的应打卡项**：目标色条 + 图标名称 + 三个大按钮 [✓ 完成] [◐ 做了一点] [— 跳过]；点击即存，按钮按下有 spring 微缩放 + 打卡项滑向"已完成"分组的动效。
- **打卡为任务级**（记录按 `目标+任务+日期` 存，2026-07-21 起）：单任务目标沿用「关联任务名 + 卡头三键」布局；一个目标下有多个并行在办任务时，卡头下逐任务成行，各行独立记状态/时长，互不覆盖（持续性项目按任务统计投入时长的核心）；目标进"已完成"分组需其当日全部在办任务都已记录。streak/热度/时长统计仍按目标聚合。
- 每项（任务）可展开：分钟 chips（15/30/60/90/自定义）+ 一句话备注。
- 顶部横向滚动一排"最近 7 天"微型日历，每天显示当日完成率小环，点击可切到那天补卡。
- 底部："昨天有 N 项缺卡 → 一键补卡"入口；正处于免打卡区间的目标显示"休息中"而非按钮。
- 全部完成时显示当日 streak 汇总 + 随机一句简短鼓励。
- **移动端（<768px）**：应用默认路由落在此面板，按钮加大到拇指友好（≥44px 触达区）；甘特图在手机上提供只读月视图（横向滚动、双指缩放、点打卡点可打卡，不做拖拽编辑）；底部 tab 导航：打卡 / 甘特图 / 复盘 / 设置。

## 六、批量操作与效率功能

- **批量操作条**（多选后底部浮出）：整体平移 N 天（输入框±）/ 改状态 / 改所属目标 / 删除；操作条上实时显示已选数量。

- **周期规则**自动生成应打卡日；**复制并顺延**一键生成衔接的下一阶段任务。
- **命令面板（`/` 或 Ctrl+K）**：模糊搜索任务/目标/操作（"新建任务""切到3月""导出JSON"均可作为命令执行），回车跳转并高亮定位。
- **撤销/重做**：覆盖一切增删改（拖拽、打卡、批量、行内编辑），历史栈 ≥ 50 步；每次 undo 在左下角 toast 显示被撤销的内容摘要。

## 八、视觉设计系统（必须高标准执行）

- 整体气质对标 **Linear / Height / Cron**：高信息密度、克制、精致、安静。绝不做花哨仪表盘风，绝不用米色底+衬线大标题+陶土色的模板化配色。
- **设计令牌先行**：开工前先产出 `tokens.css`——中性色阶（背景/面板/边框/文字四层 × 深浅主题）、5 个目标预设色（彼此区分度高、深浅主题下均清晰、色弱可辨，每色附 100%/40%/15% 三档透明度变量）、语义色（成功/警示/危险/信息）、圆角（4/6/10px 三档）、阴影两档、间距 4px 基准。全部组件只允许引用令牌。
- 字体：正文系统 UI 字体栈（中文渲染优先）；日期刻度、数字、时长一律 `font-variant-numeric: tabular-nums` 等宽数字，保证时间轴刻度与网格列纵向严格对齐。字号阶：11/12/13/14/16/20。
- 动效：只保留有功能意义的——拖拽跟手、落位归位 120ms、打卡确认 spring、今日线平滑滚动、缩放过渡 150ms、抽屉滑入 200ms；缓动统一 `cubic-bezier(0.25, 1, 0.5, 1)`；respect `prefers-reduced-motion`。
- 深色主题是一等公民：不做滤镜反色，热度条/打卡点/周末底纹在深色下单独调校对比度；bar 在深色下加 1px 内描边防止与背景糊在一起。
- 空状态有引导（首次进入引导创建第一个目标，并提供"载入示例数据"按钮）；危险操作（删除目标及其打卡记录）弹确认并说清后果；文案全部简体中文、动词开头。
- **界面语言：简体中文。**

## 十、数据层与 Supabase 云同步（必做）

架构原则：**本地优先（local-first）**。UI 永远只读写本地 IndexedDB，保证秒开与离线可用；同步引擎后台负责本地 ↔ Supabase 双向同步。断网一切照常，联网自动补同步。

- **repository 层**：`GoalRepo / TaskRepo / CheckInRepo / MilestoneRepo / ExemptionRepo / ReviewRepo / FocusRepo`，UI 不直接碰 Dexie 或 Supabase。
- **表清单（7 张实体表）**：`goals / tasks / milestones / checkIns / exemptions / reviews / focusSessions`（远端 snake_case，`focus_sessions` 由 `0002_focus_sessions.sql` 建）。加表时 `TABLE_NAMES`、`hydrate` 的 `set()`、`TABLE_LABEL` 三处漏改不会编译报错，逐处清单见 `docs/POMODORO_SPEC.md` §四。
- **同步元数据**：每条记录 `updatedAt`（写入即刷新）+ `deletedAt` 软删除（同步后 30 天真删）。
- **策略**：整行 last-write-wins（按 updatedAt），维护 `lastSyncedAt` 游标做增量推拉。单人两设备足够。
- **触发**：启动时、窗口重获焦点、本地写入后防抖 3 秒、每 5 分钟；顶栏同步状态点（✓/⟳/离线/⚠），点击手动同步与查看详情。
- **Supabase**：表与本地一一对应，均含 `user_id`，RLS：`user_id = auth.uid()`；生成完整建表+RLS 的 SQL migration 并在 README 写清在 SQL Editor 执行的步骤。认证用邮箱+密码；未登录可纯本地用，登录后本地数据全量上传合并。`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` 走 `.env.local`（附 `.env.example`），绝不硬编码。
- JSON 导出/导入保留为兜底备份。
- **部署**：README 写 Vercel 部署步骤（连仓库、配环境变量）与手机 PWA 安装方法。
