# 番茄钟 / 时间追踪的设计取舍参考（面向 YearFlow）

> 结论先行：成熟产品分成两个血统 —— **时间追踪血统**（Toggl / Clockify：一切都是 `(start, stop)` 区间，报表由区间聚合，数据可编辑，主打小时）与**番茄血统**（Pomofocus / Forest / Focus To-Do：一个番茄是一个仪式单位，主打完成个数，数据基本不可编辑）。YearFlow 的既有语义（`CheckIn.minutes`、年度堆叠面积图、投入时长排行）已经站在**时间追踪血统**这一侧；番茄只是它的节律外壳。凡在两者冲突时，一律按"分钟是货币、番茄是节奏"裁决。

---

## A. 八个必答设计问题

### 1. 会话数据模型

**常见做法**
- Toggl / Clockify：一条 time entry = `(start, stop)`，**没有"暂停"概念** —— 暂停就是 stop 再开一条新的。所有报表（今天多少小时、按项目分布）都是区间聚合。
- Pomofocus / Focus To-Do / Session：一个"完成的番茄"是一条记录（或干脆只存"今天 N 个 + M 分钟"的日聚合）；短/长休息通常不落库或只作 type 标记。
- Forest：一次会话 = 一棵树，**中途放弃留痕（枯树）** 且是核心情感机制。

**分歧点**
- 番茄计数模型简单，但回答不了"我几点在干什么"，且**跨配置不可比**（25 分钟档的 4 个番茄 ≠ 50 分钟档的 4 个）。
- 暂停存法：`pauses: {at, resumeAt}[]` 精确但编辑/同步复杂；只存 `elapsedMs` 简单但**丢失时间轴位置** —— 于是无法做跨天归属，也无法做"截断到我离开的时刻"。
- 中断留痕：Toggl 全留（工作即数据），番茄类多丢弃未完成番茄（怕污染"番茄数"这一荣誉指标）。

**对 YearFlow 的建议**
- **一条记录 = 一次专注会话，存 `startAt` / `endAt` 绝对时间戳 + 派生 `focusMs`，不是"一个番茄"。** 理由：本项目的权威口径是分钟（`monthlyGoalStats.minutes`、`minutesByGoalByMonth`、年度总时长卡都是分钟求和）；番茄个数可以从 `focusMs / plannedFocusMs` 派生，反之不行。将来把默认改成 50/10，分钟统计仍连续可比，番茄个数会断层。
- **暂停用区间数组存**（`pauses: {at: string, resumeAt?: string}[]`），`focusMs = endAt - startAt - Σ暂停`。理由：跨天归属、"忘记停"截断、以后画一条"今天的时间线"都需要时间轴位置，累计秒数一律做不到。嵌套对象在本项目零成本 —— Supabase 每表 `data jsonb` 存整实体（`Recurrence` / `baseline` 已是先例）。**但给上限**：pauses 超过 ~20 段就合并，防狂点暂停把同步行撑大。
- **中断/放弃要留痕，但用 `outcome: 'completed' | 'stopped' | 'discarded'` 分层，而不是删除。** 留痕的复盘价值极高（"今天开了 6 段只完成 2 段"是被打断的证据，比"今天 50 分钟"信息量大）；`discarded` 的 `focusMs` 记 0 / 不进分钟统计，噪音就被一个字段隔离了。反过来"中断即删除"在有软删 + LWW 同步的系统里最脏（删了又被拉回、undo 语义混乱）。
- **短休息 / 长休息不落库。** 它们不参与本项目关心的任何统计（投入时长、打卡、streak），落库却要处理"休息中切任务/关页面/跨天"一整套边界，是纯负债。休息只是运行时状态（localStorage 里的 runtime 字段）；真想记，在会话行上加个 `breaksTaken: number` 就够（P2）。

### 2. 与任务的关联

**常见做法**：Toggl 明确鼓励"先开始，后描述"（空描述条目合法）；Focus To-Do 强制先选任务；Session 用 category，可后填。

**分歧点**：先归类降低脏数据、但把摩擦放在了最不该有摩擦的时刻（人想马上开始专注时最不想做分类决策）；后归类会积累一堆 untagged 时间，Toggl 用户最常见的抱怨就是"月底清洗未分类条目"。

**对 YearFlow 的建议**
- **允许"先开始"，但把归类做成必须完成的收尾。** 启动一次点击即可（默认预选 = 今天最近一次打卡/番茄的 `goal+task`，或今天待打卡里唯一在办的任务）；会话结束的结果卡上，若无归属则高亮要求选择；打卡页顶部常驻"N 段未归类 → 去归类"入口。理由：YearFlow 所有统计都按 goal/task roll-up，**未归类会话是所有视图里的黑洞**（比 Toggl 更严重，Toggl 至少还有总时长），所以不能靠用户自觉；但强制先选会毁掉"番茄钟当专注开关"的日常手感。
- **一个会话不允许跨多任务。** 多归属会立刻引出"时间分摊比例"这一整套东西（Clockify 级复杂度），单人工具收益接近零；而且 `CheckIn` 的键是 `goal+task+date`，多归属根本没法映射过去。
- **进行中切任务 = 切断并续开（落两条），不是改归属。** 前 10 分钟做 A、后 15 分钟做 B，任何"改归属"都会把 10 分钟错记给 B —— 数据说谎。UI 上做成一次点击"切到任务 X"：保存当前段 + 立刻开新段，**倒计时不中断**（这是关键手感，否则用户宁愿不切）。
- 已结束的会话**可以**改 `taskId`（选错了要能修），但这属于"编辑"（见 Q5），与"切分"在概念和 UI 上分开。

### 3. 统计口径

**常见做法**：番茄类主打完成个数（游戏化），追踪类主打小时，混合类两个都给（于是常出现两个互相矛盾的数字）。

**分歧点**：番茄个数不可跨配置比较、还会诱导"凑整"（做了 22 分钟不算，于是硬撑或干脆放弃）；分钟诚实但少了节奏感。

**对 YearFlow 的明确建议**
| 项目 | 裁决 | 理由 |
|---|---|---|
| 权威货币 | **专注分钟（Σ`focusMs`，排除暂停与休息）** | 无缝对接既有 `minutes` 语义与三处复盘统计；引入第二货币必然产生两个不一致的"投入时长" |
| 番茄个数 | 只在番茄钟自己的界面/日目标里显示，**不进复盘** | 跨配置不可比；一旦进了年度总览就再也改不动默认时长 |
| 被打断的 12 分钟 | **算进分钟**，但不计"完成番茄数" | 真实投入就是真实投入；清零等于数据说谎，还会诱导用户挂着计时不敢停 |
| 休息时间 | **不算** | 同 Q1；且"休息也算投入"会让日投入虚高 ~20% |
| 暂停时段 | **不算**（从 focusMs 扣除） | 暂停的语义就是"这段我不在" |
| 极短会话 | **< 60 秒不落库**，toast "太短，未记录" | 防误触噪音，不是防作弊 |
| 跨天会话（23:50 开始） | **整段归属开始日**，冗余存 `date` 字段 | ① 一条会话必须能映射到唯一 `date` 才能与 `CheckIn` 的 `goal+task+date` 对齐；② "昨晚学的那 40 分钟"的心智属于昨天，与 streak 心智一致；③ 拆两条会让编辑/undo 一次动两行 |
| 自定义"日切换点"（如 04:00） | **不做** | 违反项目铁律（一天边界 = 本地 00:00），且会让 streak/热度/番茄三套口径分叉。改为：结果卡上明确写"计入 8月11日"，并给一键"改归到 8月12日" —— 显式显示 + 可覆盖，比隐式规则安全 |

（跨 2 天以上的会话由 Q4 的自动截断兜住，不会存在。）

### 4. "忘记停"防护

**关键认知**：忘记停本质是**正计时/秒表模式**的病。番茄模式天然有上限，是最强的防护 —— 前提是"到点即结束"的结算用**计划终点**而不是"用户回来点停的时刻"。

**常见做法**：Toggl 桌面端读系统级输入做 idle 检测，弹三选一 —— *keep idle time / discard idle time（停在离开时刻）/ discard and continue*。网页端拿不到系统输入，只能观测本页面的 pointer/key/visibility。

**分歧点**：浏览器里的闲置检测极不可靠（用户在 IDE 里写代码 —— 正是他在做那个任务 —— 会被判 idle）；自动截断会误砍真实的深度工作（读书 90 分钟不碰键鼠）。

**分档建议**
- **值得做（P0）**
  1. 倒计时到点即结算，`endAt = 计划终点`（不是回来点停的时刻）。这一条消掉 90% 的问题。
  2. **一切时长用绝对时间戳算，不靠累加 tick**（详见坑 #1/#2）—— 睡眠/节流/关机后恢复，数值仍正确。
  3. **恢复页面时的结算对话**：发现有 runningSession 且 `now` 远超计划终点 → 弹一次卡："发现一段未结束的专注（14:02 开始，已 3 小时 12 分）。[按计划 25 分钟记] [记到我离开的 14:41] [丢弃]"。这是网页端唯一能真正救回数据的机制，成本极低。
  4. **`lastHeartbeatAt` 心跳**（可见时 15–30s 一次，写 localStorage，**不写 Dexie**）：为"我离开的时刻"提供依据。这是网页端能拿到的最好近似，且不需要任何权限。
  5. **最大时长硬截断**（默认 4h）：超过就在结算时默认选"截断到心跳时刻"，绝不产生 12 小时的假记录。
- **该有（P1）**：`needsReview` 标记（结束时间靠心跳推断的、或超 2× 计划时长的会话），在会话列表给个待确认徽标。统计里**照常计入但标注** —— 不要做"待确认的不算"的第二套口径。
- **别做（P2）**
  - **自动闲置扣时/自动暂停**：浏览器只能观测本页面焦点，误砍真实投入的伤害远大于收益。**只观测、不自动扣，把判断权交给结算对话。**
  - `IdleDetector` API（Chrome 专有 + 需权限 + Safari 无）：单人工具不值得引入平台分叉。
  - 用 Service Worker "续命"后台计时：SW 会被杀，还会造成"以为在跑其实没跑"的更坏结果。

### 5. 手动补录与编辑

**常见做法**：Toggl / Clockify 完全可编辑 + 手动添加（工时要能对账，这是核心功能）；番茄类多不可编辑（保护"番茄不可伪造"的仪式），Forest 把不可伪造做到极致。

**分歧点**：可编辑 → 可信度取决于自律；不可编辑 → 数据必然有缺口（忘记开、在纸质书上学、在手机上看课），用户很快就不信统计了，然后不再看。

**对 YearFlow 的建议**
- 单人工具、唯一读者就是记录者，**防作弊毫无意义，缺口才是真敌人**。所以：允许事后补一段、改时长、改任务、改归属日、删除；全部走既有 `execute` 进 undo。
- **但必须留 `source: 'timer' | 'manual'`（外加 `editedAt?`）。** 理由不是防作弊，而是两个实用价值：① 自我诊断 —— "这个月 40 小时里 30 小时是手补的"说明番茄钟没被用起来，这本身是有效信号；② Q8 的合并口径需要区分"哪些分钟是我声明的、哪些是机器测的"。
- **UI 上让手动补录比启动计时器"稍微不方便"**（收进会话列表里，不放主按钮旁），保持默认路径是真实计时。标记用中性小徽标"手动"，不要用红色警示 —— 惩罚性视觉会让用户干脆不补录，缺口反而更大。

### 6. 节律与配置

**常见做法**：25/5/15、每 4 个长休息；Focus To-Do / Pomofocus 全项可配 + 自动开始 + 严格模式。

**分歧点**：配置项看起来"加一个开关而已"，实际成本在两处：污染统计口径（番茄数跨配置不可比）+ 分支组合爆炸（自动开始 × 严格模式 × 通知 × 移动端后台）。

**建议**
- **P0（就是番茄钟的定义本身，且只影响倒计时、不影响口径）**：专注时长（预设 25/45/50 + 自定义）、短休息 5、长休息 15、长休息间隔 4。
- **P0（长期日用的生存条件）**：声音开关 + 通知开关。打扰类必须能单独关，否则第一周就会被用户整个关掉。
- **P1**：`自动开始休息`（默认**开**）与 `自动开始下一段专注`（默认**关**）—— 两个独立开关。**这个默认组合有硬理由**：自动开休息无害；自动开下一段专注 + 忘记停 = 系统在你离开后自动伪造一整晚的专注记录，是最容易毁掉统计可信度的单点。
- **P1**：日目标（今天 N 个番茄 / M 分钟）—— 因为 YearFlow 有打卡心智，日目标能自然接到"建议记为完成"上（见 Q8）。
- **P2 / 别做**：严格模式（禁止暂停）、网站拦截白名单、多套预设 profile、每任务独立时长、白噪音音效包、成就徽章。这些是订阅制产品的差异化卖点，在单人工具里是纯维护成本；真想要"不许暂停"，把暂停按钮去掉就是了 —— 不必做成配置项。
- **配置存哪**：进 `AppSettings`（与 theme/ganttView 同类，设备本地、**不同步**）→ 零 SQL 改动。代价是换设备重设一次，单人两设备可接受，写进已知局限即可。**不要为了同步几个整数去动 `TABLE_NAMES` / SQL 白名单。**

### 7. 界面形态

**常见做法**：Session / Forest 走沉浸全屏；Toggl 走菜单栏微型计时器 + mini timer 窗口；Pomofocus 本身就是一屏大数字。

**分歧点**：全屏有仪式感但与"一边看甘特图一边计时"直接冲突；常驻迷你计时器信息密度友好但仪式感弱、且容易忘记它在跑。

**对 YearFlow 的建议**（主战场是甘特图，工具是"陪着我工作"的，不是"占据屏幕"的）
- **P0 顶栏常驻胶囊**：任务名（截断）+ 剩余时间（`tabular-nums`）+ 暂停/停止，全站可见。倒计时**不能每秒重渲整树** —— 直写 DOM 或用独立的细粒度订阅（项目已有 mini-map 取景框直写 DOM、dragHint 单例的成熟做法可直接照抄）。这同时是"忘记停"的第一道视觉防护。
- **P0 `document.title` 前缀**：`24:31 · MM 模块 — YearFlow`。切到别的标签页也看得见，成本极低，是网页端最有效的常驻提醒。favicon 进度环可选（P1；项目已有年度进度环图标的生成经验）。
- **P0 到点提示**：页内醒目结果卡 + 声音（可关）+ Notification（已授权才用，可关）。三者独立开关。
- **P1 全屏专注模式**：点胶囊展开（大号剩余时间 + 当前任务 + 今日已投入），Esc 退出。真正"开始专注"的那一刻需要一个把其他信息清掉的仪式；但它是可选的一层，不是唯一形态。
- **P0 键盘（有两个必须避开的坑）**：
  - **不要用空格开始/暂停** —— SPEC 4.5 明确"按住空格+拖拽 = 抓手平移"，抢了会毁掉甘特图手感。建议 `P` 开始/暂停。
  - **不要用 Esc 放弃会话** —— Esc 在本项目是"取消当前操作/关闭浮层"的通用语义（拖拽取消、popover 关闭都在用），让它放弃会话是灾难性误操作。放弃 = 显式按钮 + 确认。
- **移动端与后台不可靠的现实**：iOS 上后台标签页/未装主屏的 PWA 会被冻结，`setInterval` 停摆，Notification **无法在后台定时触发**（没有定时 Push 能力）。策略：① 时长一律时间戳重算，回前台立即正确；② **诚实降级文案**："锁屏后不会响铃"，不要假装能响；③ 提供 Screen Wake Lock 保持屏幕常亮（Safari 16.4 起支持，**装到主屏的 Web App 要到 iOS 18.4 才修好**）；④ 把移动端定位为"查看 + 补录"，主计时在电脑。这比做一堆挣扎的后台 hack 诚实且省一个数量级的工作量。

### 8. 与打卡体系的关系（本项目最关键的一题）

先把四种选择的后果推演清楚。

**方案 A：番茄完成 → 自动累加 `CheckIn.minutes`，首次写入顺带把 status 置 `done`**
- **双重计时**：用户既手填 60 分钟又跑了两个番茄 → 该是 110 还是 60？两个来源挤在同一个标量字段里**不可分辨、不可审计**，任何合并规则都会在某些天说谎。
- **undo 混乱**：一次番茄要写两张表。做成一条命令 → undo 会连带撤掉打卡，但用户可能在番茄之后手改过 status，`before` 快照会把手改覆盖掉；做成两条命令 → 用户要按两次 Ctrl+Z，中间态是"打卡有分钟但会话没了"。
- **streak 被误影响**：streak 从"我承认我做了"退化为"我开过计时器"。最危险的是误触：随手开一个番茄试音效 → 那天变 `done` → streak 续上，且几乎无法察觉。反向也坏：用户 toggle-off 删记录（现有交互：再点同状态 = 删除）会连带删掉番茄写入的分钟。
- **历史不一致**：`monthlyGoalStats.minutes` 直接 `sum(checkIns.minutes)` → 启用番茄钟那天曲线出现台阶，无法区分"更努力了"还是"计时方式变了"。
- **同步致命**：整行 LWW（按 `updatedAt`）下**累加语义天然不安全** —— A 设备 +25 推送、B 设备 +25 推送，最终是 25 而不是 50。要做对得引入 CRDT 计数器。**这是否决 A 最硬的技术理由。**

**方案 B：各自独立，统计层合并**
- 缺点只有一个但很痛：打卡点阵/streak 仍靠手动，"我明明专注了 2 小时，甘特图上这天还是缺卡"的割裂感。
- 优点全在结构上：undo 纯净（一次番茄 = 一条 sessions 命令）；同步安全（每条会话是独立不可变行，整行 LWW 天然正确，永不冲突）；历史数据零改动；streak 心智不变；131 个既有测试零风险。

**方案 C：番茄完成 → 提示"记入打卡吗"（一键，人确认）**
- 折中。保住 streak 不被误触污染，代价是每段结束多一次点击（可用"每天首段才提示"或"今天不再提示"缓解）。

**方案 D：`CheckIn.minutes` 语义升级为"人工声明值"，统计改走派生的 `effectiveMinutes`**
- 最干净的口径（不双计、可审计、同步安全），代价是 `review.ts` 三处取数要收口到一个派生函数；老数据天然兼容（没有会话 → 就用手填值）。

**推荐：B + C + D 的组合。具体六条：**

1. **新开 `focusSessions` 表，它是"真实投入"的唯一事实源。** 字段：`id / goalId? / taskId? / date（开始日，冗余便于索引与对齐）/ startAt / endAt / focusMs / plannedFocusMs / pauses[] / outcome / source / needsReview? / note? / createdAt / updatedAt / deletedAt`。行语义近似不可变（编辑 = 改整行，**没有任何需要累加的字段**）。
2. **必须开新表，不要塞进 `CheckIn`（哪怕是 `sessions[]` 内嵌数组）。** 硬理由同上：一天一行内嵌数组 + 整行 LWW = 两设备并发各加一段就丢一段；独立行永不冲突。这比"干净"更硬。
3. **统计层一处收口 `effectiveMinutes(goalId, taskId, date)`**：当天该键有会话 → 用 `Σ focusMs`；同时存在手填值时 → **取 `max(自动, 手填)`**。理由：相加必然重复计（用户手填时往往是估算整天，已含番茄那部分）；只取自动会丢掉"没开计时器的那 1 小时"；只取手填会丢掉真实数据。`max` 是"不重复计且不丢失"的最稳妥近似，而且一句话可解释（"取更完整的那个"）。配套 UI：当天有会话时，分钟输入框 placeholder 显示自动值并提示"手填将覆盖显示"，用户自然就不会重复填。（P1 可收紧成显式覆盖：有会话时分钟框只读显示自动值 + "改为手填"按钮。）
4. **打卡 `status` 永不自动写。** 结果卡上给 `[✓ 记为完成]` 按钮，走现有 `setCheckIn`，**独立成一条命令**（label 沿用"打卡「X」完成"）→ undo 语义清晰：撤销打卡不动会话，撤销会话不动打卡。
5. **streak / 热度 / 点阵口径完全不动**，继续由 `CheckIn` 驱动。streak 是自我契约，不该由传感器接管；且不动 = 既有派生缓存与全部测试零风险。
6. **用可见性弥补割裂感（这条是整套设计里最值钱的一点）**：甘特点阵/热度条上给"有专注、未打卡"一个中间态标记（如点内小竖线或半透明外环），打卡页把这些天列成"补卡建议：这天你专注了 50 分钟 → 一键补卡"。数据不自动写，但**可见性与一键补卡到位** —— 方案 B 的唯一缺点被解掉，同时一分钱信任都没花。

## C. 坑清单（现象 / 根因 / 规避）

1. **倒计时在后台变慢或停摆** — Chrome 隐藏超 5 分钟 + 链式定时器 → 1 分钟一次的 intensive throttling；iOS 后台直接冻结。→ 状态只存 `startAt/pauses`，UI 每帧从 `Date.now()` 派生；`visibilitychange` 立即重算；"到点"不靠 tick 检测，回前台时若 `now > 计划终点`就按终点结算。
2. **电脑睡眠后时长不对** — `performance.now()` 是否包含睡眠时间因平台而异。→ 时长只用 `Date.now()`；`performance.now()` 只用于动画。
3. **负时长 / 8 小时假会话** — 系统时钟被 NTP 校正、用户改时区。→ 结算时 clamp（`0 ≤ focusMs ≤ maxSessionMs`），越界标 `needsReview`；`date` 从 `startAt` 派生**一次并冻结在字段里**，绝不每次显示时重算（跨时区旅行会整片漂移）。
4. **刷新丢失进行中会话 / 云端被心跳刷爆** — 进行中状态写进了 Dexie 实体表 → 每次心跳刷 `updatedAt` → 触发防抖同步推送，还进了 undo 栈。→ 进行中一律 localStorage 同步写（不走 500ms 防抖、不进 undo），只有**结束时**才落库一条命令。
5. **双开导致双记账** — PWA 与浏览器标签页同时在跑。→ BroadcastChannel/storage 选主，非主页面只显示；落库前按 `startAt` 幂等去重。
6. **到点没声音** — autoplay policy 拦截。→ 首次点击"开始"时解锁并复用同一个 `AudioContext`（resume + 播一段静音）；同时不承诺后台标签页/锁屏能响。
7. **通知迟到或重复** — 后台无定时触发能力；SW autoUpdate 后旧页面还在跑。→ 通知只在页面存活时发；被拒权限时降级为 title 闪烁 + 页内卡。
8. **undo 栈被一个会话吃满** — 每次暂停/恢复都 `execute`，100 步栈瞬间挤掉甘特操作。→ 所有中间状态不进 undo，一次会话只产生一条命令（label 如"记录专注 25 分钟「MM 模块」"）。
9. **per-goal 派生缓存全量失效** — 会话写入替换了 tasks/checkIns 的 map 或重建了未变实体。→ 只换 `focusSessions` 的表引用（遵守既有"未动实体保持引用"铁律）；甘特若要显示"有专注未打卡"，走一个按 goal 分组、独立 memo 的轻量 `Set`，别把整个 sessions 表塞进 `useGanttDerive` 的输入。
10. **LWW 覆盖丢累加值** — 任何"行内累加"字段（`minutes += `、`sessions.push`）在整行 LWW 下都会丢。→ 一次会话一行；任何跨设备并发的量必须是"多行求和"而不是"一行累加"。
11. **月总时长与日和不一致** — 先取整成分钟再求和。→ 存 ms/秒，只在显示层取整；聚合永远从原始值算（项目在年度总时长卡上已经踩过同类：不累加月度四舍五入值）。
12. **两处算月份不一致** — 一处按 `startAt` 的月、一处按 `date` 的月，跨月的 23:50 会话在两张图里各算一次或都不算。→ 所有统计只认 `date` 字段，全项目一种算法。
13. **新表接不上同步/备份** — 新表要同时改五处：Dexie `version(2)`（**加表必须升版本**，与加字段不同）、`supabase/migrations/0002_*.sql`（建表 + RLS + `server_updated_at` 触发器）、`upsert_rows` RPC 里的**硬编码表名白名单**、`engine.ts` 的 `TABLE_NAMES/REMOTE_TABLE`、`backup.ts` 的 zod schema。漏任何一处都是静默不同步（最难发现的一类 bug）。→ 上线前逐项核对 + 一次真实两设备往返实测。
14. **免打卡区间 / 「随缘」任务被漏掉** — 免打卡只该影响"缺卡与应打卡判定"，不该影响投入时长；`adhoc` 任务不进 `dayEntries`，若任务选择器只列 `dayEntries`，随缘任务就永远统计不到时间。→ 选择器默认列在办任务（含 adhoc），可搜索全部；出差期间的专注照常计入时长。
15. **给日期范围外/已完成任务计时** — 8 月给一个 3–5 月的任务记时间。→ 提示但不阻止（真实情况就是任务延期了），顺手给"延长任务到今天"的快捷动作。
16. **移动端锁屏后一切停摆** — 平台限制，不是 bug。→ 诚实文案 + Wake Lock（Safari 16.4 起；**装到主屏的 Web App 需 iOS 18.4+**）+ 回前台时间戳重算兜底。
17. **"自动开始下一段"制造整夜假记录** — 自动续开 × 忘记停。→ 该开关默认关；且续开的段同样受 4h 硬截断与结算对话约束。
18. **手填与自动在同一天重复计时** — 用户不知道系统已经记了。→ `effectiveMinutes` 取 max + 分钟输入框展示自动值 + 会话/手填在打卡卡上并列可见（两个数、一个结论）。

## D. 对 YearFlow 的八条取舍结论

1. **数据模型**：一条记录 = 一次专注会话（`startAt/endAt/pauses[]` → 派生 `focusMs`），不是一个番茄；中断留痕但用 `outcome` 分层，`discarded` 不计分钟；**休息一律不落库**。
2. **任务关联**：允许"先开始"（默认预选上次任务），但结束时必答归类 + 常驻"未归类"清理入口；不支持一段跨多任务；**进行中切任务 = 切分成两条**，已结束才允许"改归属"。
3. **统计口径**：**专注分钟是唯一货币**，番茄个数只作节奏；被打断的 12 分钟算、休息与暂停不算、<60s 不落库；**跨天按开始日整段归属**（冗余 `date` 字段），结果卡明示归属日并可一键改归。
4. **忘记停**：做"到点按计划终点结算 + 心跳 + 恢复时结算对话 + 4h 硬截断"；**不做**自动闲置扣时、`IdleDetector`、SW 续命 —— 只观测，把判断权交给用户的一次点击。
5. **补录与编辑**：完全可编辑可补录（单人工具的敌人是缺口不是伪造），但强制留 `source: timer/manual`；手动路径故意比计时路径不方便一点，标记中性不惩罚。
6. **配置**：只要专注/短休/长休/长休间隔 + 声音 + 通知 6 项（P0），`自动开始休息`默认开、`自动开始下一段`默认关（P1）；严格模式、拦截、profile、音效包一律不做；配置放 `AppSettings`（不同步，零 SQL）。
7. **界面**：主形态是**顶栏常驻胶囊 + `document.title` 剩余时间**（直写 DOM，不每秒重渲），全屏专注是可选的第二层；`P` 开始/暂停，**空格与 Esc 都不能碰**；移动端定位为查看+补录，后台限制诚实告知 + Wake Lock 兜底。
8. **与打卡的关系（核心裁决）**：**独立新表 + 统计层收口 + 人确认打卡**。`focusSessions` 是真实投入的唯一事实源；派生 `effectiveMinutes` 以 `max(自动, 手填)` 合并；`CheckIn.status`/streak/热度**完全不动**，只提供结果卡上的一键"记为完成"（独立命令）；用甘特"有专注未打卡"中间态 + 补卡建议弥补割裂感。**绝不自动累加 `minutes`**（整行 LWW 下累加语义不安全 + 双重计时不可审计 + undo 与 streak 双重污染），**绝不自动置 `done`**（一次误触就能伪造 streak）。
