# 便签（Notes）—— 规格 v1（2026-10-29）

## 一、要解决的问题

负责人：要一个备忘录 / 便签一样的功能，生产级。方案 2026-10-29 出过一轮，七个问题负责人「全按推荐」。

**边界**：便签 = **要记住的东西**（号码、会议要点、学习思路、灵感、参考）；待办 = **要去做的事**，留在工作台。便签没有日期、没有「完成」、不进任何统计。两者唯一的桥是「转待办」。便签里的 `- [ ]` 只是记事用的勾选，不提醒、不计数。

## 二、界面

- **入口（全局）**：顶栏右侧「便签」小按钮（同步状态点左边）；快捷键 `Alt+N` 开 / 关；命令面板「新建便签」并可按正文搜便签（正文只认「包含」，不做字符子序列模糊）。手机端：同一个顶栏按钮（手机上只显示图标，在打卡页右上角），面板全宽。
- **右侧面板**（玻璃浮层、lazy 分包，宽 `NOTE_PANEL_W`；不遮挡当前页的操作语义：Esc / × / 再按 Alt+N 关，点外面不关 —— 记东西时常要对照页面内容）：
  - 顶部一个框 = **搜索 + 新建**：打字即过滤（多个词同时满足；`#标签` 词按标签过滤），回车 = 以这段文字新建一条并清空，Ctrl+Enter = 新建并展开编辑。
  - 标签条：正文里出现过的 `#标签`（按使用次数），点一下 = 往搜索框填 `#标签`。
  - 列表：**置顶**（按置顶时刻倒序）→ **最近**（按 `editedAt` 倒序，改颜色 / 置顶不跳位）。底部「归档 N」「回收站 N」两个入口切换视图。
  - 卡片：颜色、首行标题、正文前 6 行预览（清单可直接点勾）、`n/m` 清单进度、相对时间、「仅本机」「冲突副本」「已转待办」小标记。悬停出操作：颜色、置顶、转待办、归档、删除。
- **编辑**：点卡片原位展开为自适应高度的输入框，打字防抖 500ms 自动保存；Esc / Ctrl+Enter / 点别处 = 收起。第一行就是标题。
- **格式**：纯文本 + 轻量标记：`- [ ]` / `- [x]` 清单（预览态可点）、`#标签`、网址可点。不引入富文本库，不支持图片 / 附件。
- **颜色**：默认 + 黄 / 绿 / 蓝 / 粉 / 紫 / 灰 6 色，全部是 tokens.css `--note-*` 令牌，深浅主题各调一套。
- **桌面版**（W4）：
  - 便签可「贴到桌面」= 独立无边框置顶小窗，可拖动拉伸、直接编辑；位置按条存本机，重开应用自动恢复。
  - 全局热键 `Ctrl+Alt+N`：在任何软件里弹出速记小框，回车存、Shift+Enter 换行、Esc 关。热键被别的软件占了 ⇒ 设置里说明。
  - 小窗 / 速记框不直接写库：经 BroadcastChannel 交给主窗（主窗内存才是唯一写入方，见 §四）。

## 三、规则

- **标题** = 第一个非空行，去掉清单前缀与行首 `#`，截 80 字。全空的便签收起编辑时自动丢弃（不进回收站）。
- **标签** = 行首或空白后的 `#词`（词里不含空白与 `#`）；网址里的 `#` 不算。
- **转待办**：整条便签 ⇒ 待处理待办（标题 = 便签标题，备注 = 其余正文）；某一行清单 ⇒ 待处理待办（标题 = 那一行）。便签 `convertedTo` 记下待办 id。一条撤销同时撤回两边。
- **删除 = 进回收站**（`trashedAt`，可恢复），回收站里「永久删除」= 软删除（`deletedAt`，走同步墓碑）。进回收站满 30 天的，面板打开时自动永久删除。
- **撤销**：新建、删除、恢复、置顶、颜色、归档、仅本机、转待办都进撤销栈；**正文编辑**一次编辑会话（展开到收起）合成一条撤销，打字过程中用输入框自己的 Ctrl+Z。
- **仅本机**（`localOnly`）：这条不上云。推送时只推一个不含正文的墓碑 ⇒ 其他设备上这条消失；关掉后再推完整一行 ⇒ 其他设备恢复。本机备份文件里仍然有它。
- **冲突副本**：同步拉到某条便签的远端新版本、而本机这条还有没推上去的修改且正文不同 ⇒ 远端版本照常生效，本机那版另存为一条「冲突副本」（`conflictOf` 指回原便签，置顶显示）。编辑器展开期间远端改了同一条 ⇒ 收起时你看到的那版存进原便签，远端那版另存为冲突副本。两边都不丢，合并完删副本即可。
- 容量：正文上限 `NOTE_MAX_CHARS`（20000 字），超出截断并提示。

## 四、数据

`Note`（domain.ts）：`body`、`color?`、`pinnedAt?`、`archivedAt?`、`trashedAt?`、`localOnly?`、`conflictOf?`、`convertedTo?`、`editedAt`、`createdAt`、`updatedAt`、`deletedAt?`。Dexie v6 新表 `notes`；云端表 `notes`（`supabase/migrations/0007_notes.sql`，`upsert_rows` 白名单是 0006 的超集）。备份 schema 缺省补空数组（老备份照常导入）。

派生纯函数 `lib/derive/notes.ts`（标题、标签、清单、搜索、排序、过期回收站）；冲突副本与仅本机推送脱敏在 `db/sync/merge.ts`（纯函数，单测）。写操作 `store/noteActions.ts`。撤销合并：`execute(label, changes, { mergeKey })` —— 栈顶是同一 mergeKey 时合并为一条（保留最早的 before）。

桌面贴纸的「哪几条贴着、在哪」是本机窗口状态，存主进程 `sticky-notes.json`，不进库、不同步。

桌面版：`note.html` + `src/note-main.tsx`（贴纸 `?id=` / 速记 `?quick=1`，`notes/NoteWindow.tsx`）；主窗侧 `notes/bridge.ts`（hydrate 之后才回话 ⇒ 贴纸在主窗起来前一直重试，不会把「还没载入」误判成「已删除」）；主进程 `electron/main.cts`「便签」一节。主窗真关了（退出 / 关窗即退出模式）连带关贴纸，位置留着下次贴回。

自查：`scripts/check-notes.mjs`（网页，vite dev）、`scripts/check-notes-desktop.mjs`（桌面，先 `npm run electron:build`；全局热键用 SendKeys 发真实按键）。
